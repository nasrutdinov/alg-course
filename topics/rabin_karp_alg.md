# Конспект: Алгоритм Рабина-Карпа (Rabin-Karp)

**Алгоритм Рабина-Карпа** — это алгоритм поиска подстроки в строке, созданный в 1987 году. Его главная «фишка» — использование **хеш-функций** и концепции **скользящего хеша** (rolling hash) для быстрого отсечения заведомо неподходящих позиций.

---

## 1. Основная идея

Вместо того чтобы сравнивать паттерн (образец) с каждым окном текста посимвольно (как в наивном алгоритме), мы сравниваем их **хеши**.
1. Вычисляем хеш паттерна.
2. Вычисляем хеш текущего окна текста.
3. Если хеши **не равны** — сдвигаем окно на 1 символ вправо (это занимает $O(1)$ времени).
4. Если хеши **равны** — делаем полную посимвольную проверку (чтобы исключить коллизии хешей).

---

## 2. Магия алгоритма: Скользящий хеш (Rolling Hash)

Если пересчитывать хеш для каждого окна текста с нуля, алгоритм будет работать за $O(n \cdot m)$, что не дает выигрыша. 
Чтобы пересчитывать хеш за **$O(1)$**, используют полиномиальный хеш.

### Формула полиномиального хеша:
Для строки $S$ длины $m$ хеш вычисляется как:
$$H(S) = (S[0] \cdot B^{m-1} + S[1] \cdot B^{m-2} + \dots + S[m-1] \cdot B^0) \pmod Q$$
где:
* $B$ — основание (обычно размер алфавита, например, 256 для ASCII).
* $Q$ — большое простое число (для уменьшения коллизий).

### Как происходит «скольжение»:
Когда мы сдвигаем окно на 1 символ вправо, мы **убираем** первый символ окна и **добавляем** новый последний.
$$H_{new} = \left( (H_{old} - S_{out} \cdot B^{m-1}) \cdot B + S_{in} \right) \pmod Q$$
*Где $S_{out}$ — уходящий символ, $S_{in}$ — приходящий символ.*

---

## 3. Оценка сложности

* **Время на предобработку:** $O(m)$ (вычисление хеша паттерна и константы $B^{m-1}$).
* **Среднее время поиска:** $O(n)$ (где $n$ — длина текста). Хеш пересчитывается за $O(1)$, коллизии случаются редко.
* **Худшее время поиска:** $O(n \cdot m)$. Возникает, если происходит очень много коллизий хешей (например, ищем `"aaa"` в тексте `"aaaaaaa..."`), и алгоритму приходится часто делать полную посимвольную проверку.
* **Память:** $O(1)$ (дополнительная память не зависит от длины строк).

---

## 4. Примеры использования

Хотя для поиска *одной* подстроки алгоритмы Кнута-Морриса-Пратта (KMP) или Бойера-Мура на практике часто быстрее, Рабин-Карп незаменим в других сценариях:

1. **Поиск множества подстрок одинаковой длины:**
   Если нужно найти в тексте сразу 1000 разных слов длиной 5 символов, мы просто добавляем их хеши в хеш-таблицу (Set) и проходимся по тексту один раз, проверяя хеши окон.
2. **Поиск плагиата и дедупликация:**
   Сравнение длинных документов. Текст разбивается на окна (например, по 100 символов), для них считаются хеши. Совпадение хешей указывает на заимствование.
3. **Биоинформатика:**
   Поиск коротких мотивов (паттернов) в длинных последовательностях ДНК (A, C, G, T).
4. **Утилиты типа `grep` или `diff`:**
   Используют варианты этого алгоритма для быстрого поиска паттернов в файлах.

## 5. Реализация на Python

Ниже приведена классическая реализация с полиномиальным хешем.

```python
def rabin_karp_search(text, pattern):
    """
    Ищет все вхождения pattern в text.
    Возвращает список индексов начал найденных подстрок.
    """
    n, m = len(text), len(pattern)
    
    # Базовые проверки
    if m == 0 or m > n:
        return []

    # Параметры хеш-функции
    BASE = 256       # Размер алфавита (ASCII)
    MOD = 10**9 + 7  # Большое простое число для взятия остатка

    # Предварительно вычисляем BASE^(m-1) % MOD
    # Это множитель для "старшего" символа в окне
    h_multiplier = pow(BASE, m - 1, MOD)

    # 1. Вычисляем начальные хеши для паттерна и первого окна текста
    p_hash = 0
    t_hash = 0
    for i in range(m):
        p_hash = (p_hash * BASE + ord(pattern[i])) % MOD
        t_hash = (t_hash * BASE + ord(text[i])) % MOD

    matches = []

    # 2. Скользим по тексту
    for i in range(n - m + 1):
        # Если хеши совпали, делаем полную посимвольную проверку
        if p_hash == t_hash:
            if text[i:i+m] == pattern:
                matches.append(i)

        # 3. Пересчитываем хеш для СЛЕДУЮЩЕГО окна (скользящий хеш)
        if i < n - m:
            # Убираем старший символ, сдвигаем хеш, добавляем новый символ
            t_hash = ( (t_hash - ord(text[i]) * h_multiplier) * BASE + ord(text[i+m]) ) % MOD
            
            # В Python оператор % всегда возвращает положительное число, 
            # поэтому добавление MOD перед % не требуется (в отличие от C++/Java).

    return matches


# ==============================
# Пример использования
# ==============================
if __name__ == "__main__":
    text = "AABAACAADAABAABA"
    pattern = "AABA"
    
    print(f"Текст:   {text}")
    print(f"Паттерн: {pattern}")
    
    indices = rabin_karp_search(text, pattern)
    print(f"Найдено на позициях: {indices}") 
    # Ожидаемый вывод: [0, 9, 12]
    
    # Проверка на коллизию (текст, где хеши могут совпадать, но строки разные)
    text2 = "ABABABAB"
    pattern2 = "ABAB"
    print(f"\nТекст:   {text2}")
    print(f"Паттерн: {pattern2}")
    print(f"Найдено на позициях: {rabin_karp_search(text2, pattern2)}") 
    # Ожидаемый вывод: [0, 2, 4]
```

## 6. Важные нюансы и советы

1. **Защита от коллизий:** Равенство хешей **не гарантирует** равенство строк. Посимвольная проверка (`text[i:i+m] == pattern`) обязательна. Без нее алгоритм будет выдавать ложные срабатывания (False Positives).
2. **Выбор `MOD`:** Чем больше простое число, тем ниже вероятность коллизии. В Python нет переполнения целых чисел, поэтому можно брать очень большие модули (например, $10^{18} + 9$), но на практике $10^9+7$ более чем достаточно.
3. **Двойное хеширование:** Если требуется экстремальная надежность (например, в криптографии или хеш-таблицах), используют две разные хеш-функции одновременно. Вероятность коллизии двух хешей стремится к нулю.
4. **Альтернативы:** 
   * Если ищете **одну** подстроку — используйте **Boyer-Moore** (он быстрее на естественных текстах) или **KMP** (гарантирует $O(n)$ в худшем случае).
   * Если ищете **много** подстрок или работаете с **потоковыми данными** — **Rabin-Karp** вне конкуренции.
